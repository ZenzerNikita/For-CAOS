# Введение в язык C

Первая часть нашего курса посвящена введению в язык программирования C.
Язык C можно считать "Lingua franca" большинства современных императивных языков программирования,
то есть их некоторой, условно говоря, общей частью, позволяющей объединять компоненты, написанные на разных
языках, в единое целое.

И в стандарте языка C, и в стандарте языка C++ специфицируется общее для двух языков вычислительное устройство,
абстрактный центральный процессор, на котором выполняются программы на C и C++. Для простоты назовём
это вычислительное устройство C-машиной.
Программы на языках Rust и Go предназначены для исполнения на C-машине.
Программы на Java и других jvm-языках, а также программы на C# и других dotnet языках выполняются на C-машине
опосредованно, через свои виртуальные машины. Таким образом, язык C можно рассматривать как язык, описывающий
функционирование современного компьютера с точки зрения языков высокого уровня.

Компоненты программ, например отдельные исходные файлы или отдельные библиотеки, написанные на разных языках
программирования, объединяются в одну исполняемую программу, предоставляя другим компонентам свое описание
в терминах языка C. Интерпретируемые языки, такие как Python, или виртуальные машины, например jvm,
обеспечивают возможность вызова компонент, написанных на других языках, специфицированных в терминах языка C.

На языке C написаны и продолжают развиваться ключевые компоненты современной компьютерной инфраструктуры,
например: ядро Linux, СУБД PostgresQL, NGINX, и так далее.

С точки зрения изучения устройства операционных систем, язык C имеет преимущество перед C++, так как C не
скрывает за толстым слоем (протекающих) абстракций вычислительную машину, на которой в итоге и выполняется
программа.

Поэтому, хотя, возможно, язык C именно в роли языка для разработки программного обеспечения сейчас используется
достаточно редко, его роль общего знаменателя и описателя машины выполнения для других языков ничуть не уменьшилась.

## История и современное состояние языка C

Язык C прошел долгую историю развития. Первое описание языка, условно принимаемое за стандарт, появилось в 1978 году
в книге Кернигана и Ритчи, поэтому эта версия языка условно называется K&R C.

Настоящий международный стандарт на язык C был подготовлен Американским институтом стандартизации (ANSI) и опубликован
в 1989 году, поэтому называется ANSI C или C89. До сих пор эта версия стандарта C используется в разработке PostgresQL
и libcurl.

Далее разработка языка C была передана в Международную организацию по стандартизации (ISO). Разработка языка C ведется более-менее
параллельно с разработкой языка C++, и ключевые изменения и уточенения в абстрактную машину исполнения вносятся синхронно и в язык C,
и в язык C++.

Следующим стандартом языка C стал стандарт 1999 года, который официально добавил в язык C многие возможности, изначально появившиеся в C++,
например возможность определения переменной в любом месте функции, а не только в её начале.

Следующим стандартом языка C стал стандарт 2011 года, который совместно со стандартом C++ 2011 определил модель памяти
и модель многопоточного исполнения.

Стандарт C 2017 года, формально опубликованный в 2018 году, не внес в язык никаких принципиальных изменений, исправив и уточнив некоторые моменты
языка и стандартной библиотеки.

Самым последним стандартом C является стандарт C23, опубликованный в 2024 году. В язык внесены изменения, синхронизирующие его с C++23.
Например, вместо трёх возможных вариантов представления знаковых целых чисел оставлен один &mdash; дополнительный код.

В дальнейшем мы будем использовать стандарт C17 в качестве основного по причине того, что поддержка стандарта C23
в текущих версиях компиляторов может быть неполной или содержать ошибки.

Из-за долгой истории развития языка и того, что некоторые возможности попадали в него достаточно поздно под влиянием более современных языков,
у новых возможностей C часто нет широкого использования в существующем коде. Почти все проекты используют не стандартный C, а его диалекты;
например, ядро Linux написано не на стандартном C, а на диалекте GNU C. В мире Windows используется не стандартный C, а его диалект Visual Studio C.
Для разработки встроенных систем под процессоры ARM используется ARM C compiler со своим диалектом C и так далее.

## Компиляторы и другие инструментальные средства

Данный курс ориентирован на работу в командной строке, поэтому мы не предлагаем и не продвигаем никакие интегрированные среды. Одним из навыков,
который вы должны освоить, является работа в командной оболочке и выполнение основных задач, возникающих при разработке, из командной строки.

Если вы работаете в какой-либо из разновидностей Linux, командная оболочка у вас уже есть. Скорее всего, компиляторы и необходимые инструменты сборки
тоже уже установлены, а если нет, то вы легко можете их установить штатным пакетным менеджером системы (apt, dnf и т. п.).

Если вы работаете в MacOS, командная оболочка у вас уже есть. Установите XCode command line tools, кроме того рекомендуется установить пакетный менеджер brew
и устанавливать программы с помощью него, так как в brew все программы намного более новые, чем в стандартной поставке.

Если вы работаете в Windows, лучше сразу установите какую-нибудь версию Linux в гостевую виртуальную машину. Самый простой способ сделать это &mdash;
установить Windows Subsystem for Linux (WSL), но возможен вариант и с установкой виртуализатора, например Virtual Box, и с инсталляцией
Linux в гостевую систему. В самом крайнем случае можно установить MinGW64.

В качестве основного компилятора мы будем использовать GNU C Compiler. Подойдёт любая не очень старая версия компилятора, например
версия 10 или выше.
Можно использовать компилятор Clang C. Подойдет любая не очень старая версия компилятора, например версия 10 или выше. Microsoft Visual Studio мы не рассматриваем
в качестве опции, не рекомендуем использовать его и не гарантируем, что рассматриваемые примеры будут работать с этим компилятором.

Кроме компилятора потребуются другие инструментальные средства: make, gdb, cmake, о которых мы будем говорить в соотвествующих разделах.

## Минимальная программа на C

Простая программа на C выглядит следующим образом:

```c
#include <stdio.h>

int main()
{
    printf("Hello\n");
}
```

Если вы знакомы с Java, то программа выглядит достаточно похоже. Это не удивительно, ведь C &mdash; это "дедушка" Java.

Эта программа состоит из следующих частей:

```c
#include <stdio.h>
```

Подключение заголовочного файла с именем `stdio.h`. В Linux этот файл можно найти в системе по пути `/usr/include/stdio.h`.
Эта конструкция аналогична импорту модулей стандартной библиотеки классов Java, но в C "импорт" выполняется с помощью
текстовой подстановки содержимого указанного файла вместо директивы `#include`. Заголовочный файл `stdio.h` содержит
определения типов данных, декларации глобальных переменных и функций, реализующих операции стандартного ввода и вывода в языке C.

"Угловые скобки", то есть знаки "меньше" и "больше" вокруг имени файла сигнализирует о том, что подставляется заголовочный файл
из системной или внешней по отношению к компилируемой программы библиотеки. В дальнейшем мы будем использовать запись
имени заголовочного файла в кавычках, когда будем подставлять заголовочный файл, являющийся частью нашей программы. Но пока мы
остановимся на единственной форме директивы `#include` &mdash; с угловыми скобками.

```c
int main()
```

Здесь определяется главная функция программы на C, то есть функция, с которой начинается выполнение программы. Она, как и во многих
других языках, называется `main`. Эта функция должна вернуть целое значение (тип `int`). После имени функции перечисляются аргументы,
которые должна принимать эта функция. Смысл пустой пары скобок `()` менялся в процессе развития языка C.
До недавнего времени пустая пара скобок означала, что функция может принимать любое количество параметров любого типа,
но в современном понимании такая функция наоборот, не принимает аргументов, что соответствует пониманию пустой пары скобок в C++.
Поэтому в программах на C могут написать:

```c
int main(void)
```

подчеркивая, что функция `main` не принимает никаких аргументов. Это &mdash; самый простой вариант определения функции `main`. Кроме него
в программах на C и C++ вы можете увидеть вариант:

```c
int main(int argc, char *argv[])
```

Этот вариант добавляет в функцию `main` два параметра, необходимые для обработки аргументов командной строки.

Реже можно встретить вариант:

```c
int main(int argc, char *argv[], char *envp[]);
```

Этот вариант добавляет в функцию `main` еще и параметр, в котором передаются переменные окружения программы.

В языке C нет перегрузки функций, то есть имени функции достаточно для того, чтобы определить какая функция будет вызвана
в данной точке программы. Как оказалось возможным, что одна и та же функция может не принимать аргуметов, либо принимать два или три аргумента,
мы рассмотрим позже. Пока же зафиксируемся на варианте `int main()`.

В любом случае функция `main` обязана вернуть значение типа `int`. Но мы видим, что в функции `main` нет оператора `return`, то есть
непонятно, какое значение возвращает эта функция. Для любой другой функции в программе это ошибка, но для функции `main` сделано исключение.
Если функция `main` завершается по достижению конца тела функции без явного оператора `return`, подразумевается возврат значения `0`.

Значение, возвращенное из `main`, называется кодом завершения программы. Точнее говоря, используется только младший байт возвращённого значения.
Код завершения 0 означает, что программа завершилась, успешно выполнив действия, для которых она запускалась. Ненулевые значения кода
завершения сигнализируют о том, что при выполнении программы возникла ошибка, которая не позволила по какой-то причине обработать входные данные.
Что означет каждое конкретное значение кода завершения можно посмотреть в документацию на соотвествующую программу. Какого-то фиксированного
стандарта на ненулевые значения кода завершения нет.

Пока же мы будем использовать самую простую форму главной функции программы:

```c
int main()
{
}
```

Эта функция не принимает никаких параметров и возвращает 0.

И наконец, тело функции `main` состоит из единственного вызова функции `printf`, которая выполняет форматный вывод указанной строки на
стандартный поток вывода.

Как и в других языках, запускаемая программа, как правило, получает три потока для ввода и вывода данных:
* `stdin` &mdash; стандартный поток ввода, используется для чтения данных для обработки.
* `stdout` &mdash; стандартный поток вывода, используется для вывода результатов работы программы.
* `stderr` &mdash; стандартный поток ошибок, используется для вывода диагностических сообщений, ошибок во время работы и так далее.

Близким аналогом функции `printf` в языке Java является `System.out.printf`, а в языке Go &mdash; `fmt.Printf`.

## Как компилировать и запускать простые программы

Итак, пусть простая программа написана и сохранена в файл на диске с именем `prog.c`.
Непосредственно запустить ее на выполнение, как это делается с программами на Python или современном Java нельзя
(ну, почти).

Исходный текст программы должен быть скомпилирован в исполняемый файл. Исполняемый файл &mdash; это файл с инструкциями
центрального процессора (ЦП)
и данными для них, пригодный для исполнения центральным процессором с минимальными накладными расходами,
как правило, заключающимися только в загрузке содержимого файла в память. Формат файла для хранения исполняемой программы
отличается от системы к системе. В большинстве POSIX-совместимых операционных систем используется формат,
называемый ELF (executable and linking format). На MacOS используется формат Mach-O, на Windows используется формат
PE (Portable Executable). В деталях устройство форматов исполняемых файлов будет рассмотрено далее в нашем курсе.
Пока же давайте предположим, что мы работаем на Linux, и нам нужно получить исполняемый файл в формате ELF.

Компиляция программы из файла с исходным кодом на языке C в исполняемый файл в формате ELF выполняется в несколько шагов,
которые также более подробно будут рассмотрены далее на курсе. Но в простых случаях мы можем использовать команду `gcc`,
которая выполнит все шаги "под капотом" и выдаст нам уже готовый исполняемый файл.

Самый простой вариант запуска команды `gcc` такой:

```shell
gcc prog.c
```

Мы выполняем команду `gcc`, передавая ей имя файла с исходным кодом программы на C.
Если в программе нет ошибок, скомпилированная исполняемая программа в формате ELF будет записана в файл `a.out`.
Такое название &mdash; это дань традиции, пошедшей от самых первых версий Unix.
Но мы будем использовать более сложную, но и более полезную командную строку для компиляции программ:

```shell
gcc -Wall -Werror -O2 -g -std=gnu17 prog.c -o prog
```

По ходу курса эта команда может видоизменяться.
Здесь опции `-Wall -Werror` включают более глубокую диагностику программы, позволяющую выявить больше ошибок,
чем при запуске по умолчанию. Опция `-O2` включает оптимизацию программы, которая нам здесь нужна,
чтобы лучше работала опция `-Wall`. Опция `-g` включает добавление в исполняемый файл отладочной информации,
которая незаменима при отладке программы. Опция `-std=gnu17` активирует поддержку стандарта C17 и некоторых
расширений стандартной библиотеки языка C. Наконец, опция `-o prog` указывает, что исполняемый файл
должен быть сохранен в файл с именем `prog`.

В итоге в текущем каталоге будет создан файл с именем `prog`, который уже можно запускать на выполнение.
Для запуска на выполнение мы указываем путь к программе, например `./prog`.
В результате запуска мы увидем строку `Hello` в окне терминала.
Код завершения только что завершившейся программы мы можем проинспектировать с помощью команды `echo $?`.

## Типы данных в языке C

Перед тем, как перейти к рассмотрению более сложной программы, обсудим простейшие типы, доступные в языке C.

### Булевский тип

Традиционно в языке C не было специального булевского типа. Для хранения булевских значений использовались переменные типа `int` или `char`.
Современные версии C явный булевский тип предлагают. Впрочем, нельзя сказать, что он широко используется. Много кода на C до сих
пор по старинке используют обычные целые типы.

В очень старом коде можно встретить собственные определения булевского типа и булевских констант, обычно с помощью директивы `#define`.
Мы не рекомендуем ни делать так самим, ни использовать готовые фрагменты подобного кода.
Начиная со стандарта C99 появился тип `_Bool` с константами `_True` и `_False`. Такие странные имена были выбраны для того, чтобы минимально
поломать уже существовавшие в то время программы, которые определяли булевский тип самостоятельно. Нельзя сказать, чтобы этот тип
сколь-нибудь широко использовался в новых программах на C. Но можно использовать заголовочный файл `<stdbool.h>`, который определял более
привычный вид булевского типа и констант:

```c
#include <stdbool.h>

int main()
{
    bool a = true;
    bool b = false;
}
```

Начиная с C23 тип `bool` стал частью языка.

### Символьный тип

Символьные типы &mdash; это типы `char`, `signed char` и `unsigned char`. На самом деле &mdash; это целые типы. Их название как символьных типов &mdash; это
тоже дань традиции. Когда-то предполагалось, что переменной типа `char` достаточно для хранения одного символа, что сейчас конечно же не так.
Типы семейства `char` занимают минимальную индивидуально адресуемую ячейку памяти компьютера. Их размер по определению равен одной единице размера,
и размеры всех других сущностей программы измеряются в единицах типа `char`.

Почти всегда, и на Windows, и на MacOS, и на Linux это означает, что размер типа `char` &mdash; 1 байт (8 битов). Однако, ещё живы предания
про 9- или 18-битные компьютеры, на которых тип `char` был соответственно 9 или 18 бит. Стандарт языков C и C++ это не запрещает.
Ну и до сих пор существуют специализированные процессоры, на которых размер типа `char` &mdash; 16 бит. Несмотря на это,
поскольку мы рассматриваем C как язык системного программирования для POSIX-совместимых операционных систем
или для выпускающихся сейчас широко распространённых процессоров, мы будем считать,
что тип `char` имеет размер 8 бит.

Тип `char` имеет два варианта: знаковый тип `signed char`, который допускает диапазон целых значений `[-128; 127]`,
и беззнаковый тип `unsigned char`, который допускает диапазон целых значений `[0; 255]`.
По определению модификаторы типа `signed` и `unsigned` не меняют битность типа, то есть знаковый и беззнаковый типы гарантированно
имеют размер 8 бит, если тип `char` имеет размер 8 бит.

Возникает вопрос, а какой же сам тип `char`? Он знаковый или беззнаковый? Это &mdash; одна из бед языков C и C++. Дело в том,
что он может быть и таким, и таким. Знаковость типа `char` &mdash; это Implementation defined поведение языка,
то есть, конечно, для каждой аппаратной платформы и компилятора, знаковость типа `char` известна и фиксирована,
но в целом &mdash; нет. Например, на процессорах Intel семейства x86 компиляторы C традиционно рассматривают `char` как знаковый тип,
а на процессорах ARM &mdash; как беззнаковый. То есть даже минимально переносимая программа, которая предназначена для работы и на
x86-, и на ARM-процессорах, не может делать предположения о знаковости типа `char`.

Учитывая то, что в языке C строки хранятся в массивах типа `char`, а в C++ в контейнере `std::basic_string<char>` a. k. a. `std::string`,
обработка UTF-8 строк становится в каком-то смысле игрой в футбол на минном поле...

Принудительно задать знаковость типа `char` можно с помощью опций компиляторов gcc/clang `-fsigned-char` или `-funsigned-char`,
но нет гарантий, что эти опции ничего не сломают в интерфейсах стандартной библиотеки.

### Другие целые типы

Для остальных целых типов действует правило, что явное указание знаковости с помощью `signed` ничего не значит, то
есть `signed int`, `signed`, `int` &mdash; это один и тот же тип. Знаковый и беззнаковый варианты типа гарантированно
имеют одинаковое количество бит двоичного представления.

Типы `short` и `unsigned short` универсально имеют размер 16 бит.

Существуют и достаточно популярны платформы, на которых тип `int` имеет размер 16 бит. Это AVR, в просторечии известный как Arduino.
Но для основных 32- и 64-битных платформ Intel x86, ARM и RiscV тип `int` имеет размер 32 бита.
Более того, спецификация POSIX для операционных систем требует, чтобы `int` был 32-битным. Мы в дальнейшем будем подразумевать
32-битность типа `int`, кроме тех случаев, когда нам по какой-то причине потребуется другой размер. Такие случаи будут
оговариваться явно.

Тип `long` имеет два варианта размера: 32 и 64 бита. Тип `long` 32-битный на 16-битных платформах, том же самом AVR,
на 32-битных платформах (и Windows, и POSIX), для совместимости с 16-битными платформами, и на WoW64 (64-битный Windows)
для совместимости с 32-битными платформами. Однако на 64-битных POSIX-совместимых операционных системах он 64-битный!
Из-за того, что размер типа `long` так варьируется, мы будем избегать его использования, кроме случаев, где это
диктуется требованиями к передаче параметров в или возврату значений из стандартных функций.
Кстати, можно писать `long int` или `int long`, но никто так не делает.

А вот тип `long long` универсально имеет размер 64 бита. Но на 16- или 32-битной платформе манипуляции с 64-битными числами,
особенно деление и взятие остатка и в меньшей степени умножение, реализуются программно и существенно медленнее,
чем операции со значениями "своей" битности. Поэтому не нужно использовать тип `long long` там, где можно обойтись
и 32-битным `int`. При программировании на C мы целимся в максимальную эффективность программы, а
бесконтрольное использование `long long` может этому помешать.

Вот так:

```c
#define int long long
```

делать никогда не надо!

Типа `long long long` не существует, но на 64-битных платформах можно использовать тип `_int128`. Впрочем, к нему применимо
то же замечание, что и к типу `long long` на 32-битных платформах. Кроме того, в стандартной библиотеке Си отсутствуют
некоторые полезные функции для работы с 128-битными целыми числами.

### Типы с плавающей точкой

В языке C есть типы `float` и `double` для 32-битных и 64-битных чисел с плавающей точкой.
Кроме того есть тип `long double`, но его можно отнести к легаси типам, специфичным для 32-битной архитектуры Intel x86.
На некоторых платформах реализована поддежка 16-битного типа `_Float16` или 128-битного типа `_Float128`.

### Типы фиксированной битности

В заголовочном файле `<stdint.h>` определены типы с фиксированной битностью.
Например, `int8_t` &mdash; это 8-битный знаковый целый тип (то есть `signed char`),
а `uint8_t` &mdash; это 8-битный беззнаковый целый тип (то есть `unsigned char`).
`uint64_t` &mdash; это 64-битный беззнаковый тип.

Эти типы могут быть полезными, когда нужно определить структуру с фиксированной раскладкой по памяти,
но просто так их использовать в программе не стоит. Считать значение такого типа или вывести его
может вызвать затруднения и уж точно сделает вашу программу намного менее читабельной,
чем использование обычных `int` и `long long`.

### Размеры типов

Как было сказано выше, размеры всех сущностей, в том числе типов, измеряются в единицах типа `char`.
Поэтому, подводя итог, мы можем свести размеры в такую таблицу:

| Type | Size |
| - | - |
| `char`, `signed char`, `unsigned char` | 1 |
| `_Bool`, `bool` | 1 |
| `short`, `unsigned short` | 2 |
| `int`, `unsigned int` | 2 (редко - Arduino), 4 - почти везде |
| `long`, `unsigned long` | 4, 8 (64-битные POSIX-совместимые системы) |
| `long long`, `unsigned long long` | 8 |
| `_int128` | 16 (только 64-битный gcc/clang) |
| `float` | 4 |
| `double` | 8 |
| `_Float16` | 2 (может не поддерживаться) |
| `_Float128` | 16 (может не поддерживаться) |

## Структура программы

Программа, а точнее единица компиляции, но пока для нас это одно и тоже, представляет собой последовательность 
определений (definitions) и объявлений/деклараций (declarations). Объявление вводит в программу новую сущность, но не создаёт ее,
то есть не выделяет память под переменную, не генерирует код для функции и так далее. После декларации можно
с некоторыми ограничениями использовать эту сущность. Например:

```c
int work();
```

Это декларация функции `work`, которая не принимает параметров и возвращает результат типа `int`.
После декларации идентификатор `work` становится доступным для использования, и мы можем, например,
вызывать эту функцию.

```c
extern int secret;
```

Это декларация переменной `secret` типа `int`. Начиная с этой точки в программе можно использовать
идентификатор `secret` для работы с этой переменной.

```c
struct Item;
```

Это декларация структурного типа. После этой точки в программе можно использовать `struct Item` &mdash; например,
для объявления параметров функции.

В программе может быть сколько угодно деклараций одной и той же сущности при условии, что декларации
не противоречат друг другу.

Определение сущности вводит в программу эту сущность и создает её. Например:

```c
int work()
{
    return 42;
}
```

Создает тело функции, выполняющее заданные действия. Машинный код для этой функции размещается в исполняемом файле.

```c
int secret = 123456;
```

Выделяет память под переменную `secret` и инициализирует её значением 123456.

```c
typedef int myint;
```

Определяет синоним для типа `int`.

```c
struct Item
{
    double x;
};
```

Определяет структурный тип.

Декларации сущности не должны противоречить определению. Каждая сущность должна определяться в программе ровно один раз
(one definition rule &mdash; ODR). Все определения одного и того же типа в разных единицах компиляции должны быть текстуально
идентичны.

## Определения функций

В языке C функции могут быть определены только на верхнем уровне программы. Функции не могут быть вложены
в другие функции. Функции не могут быть вложены в другие типы данных, например структуры.
Определение функции состоит из типа возвращаемого значения, имени функции и параметров функции,
записываемых через запятую, после которых следует блочный оператор.

```c
unsigned upow(unsigned a, unsigned b)
{
    return b ? upow(a, b - 1) * a : 1; 
}
```

(Это плохая реализация возведения в степень, не делайте так!)

Замечание для знакомых с Go: писать тип параметра нужно каждый раз, написать `unsigned a, b` нельзя! Кроме того, функция может возвращать
только одно значение.

Аргументы всегда передаются в функции по значению, включая структурные типы. Для типов массивов можно условно говорить, что они
передаются в функции по ссылке, но на самом деле работает механизм неявного преобразования массива в указатель и передача указателя
по значению.

Если функция не возвращает значения, вместо возвращаемого значения записывается ключевое слово `void`. Например:

```c
void fail_badly(int reason)
{
}
```

## Управляющие конструкции

Управляющие конструкции языка C очень похожи на соответствующие конструкции языка Java. Собственно, Java их из C++ и позаимствовал.
Базовые управляющие конструкции следующие:

### Условный оператор

```c
if (expression) statement
```

или

```c
if (expression) statement
else statement
```

В языке C почти любое значение может использоваться на месте булевского. Нулевое значение, будь то это целочисленный 0, вещественный 0
или нулевой указатель, равнозначно булевому `false`, а ненулевое &mdash; булевому `true`. Соответственно, операции сравнения на равенство или неравенство
с нулём часто опускаются.

Еще одно замечание для знающих язык Go: скобочки вокруг выражения обязательны и являются частью оператора `if`, а не выражения.

Хотя формально в теле оператора `if` может использоваться одиночный оператор, из соображений читаемости и стиля кодирования
предпочтительнее использовать блочный оператор. Например, вместо

```
if (x > 0) y = x;
```

предпочтительнее писать

```
if (x > 0) {
    y = x;
}
```

Такие правила часто собираются в руководство по стилю кодирования и настраиваются в инструментах для автоматического форматирования кода,
например `clang-format`. В C, в отличие от Go, нет единого жестко стандартизированного стиля оформления кода, но есть несколько
наиболее популярных вариантов, один из которых мы будем использовать.

### Операторы цикла

```c
while (expression) statement
```

Цикл с предусловием. Выполняется, пока `expression` вычисляется в `true`. Распространенная форма записи бесконечного цикла: `while(1) { ... }`.

```c
do statement while(expression);
```

Цикл с постусловием. Выполняется, пока `expression` вычисляется в `true`. Отличие от предыдущей формы цикла в том, что цикл while может
не выполниться не разу, а цикл do while выполнится хотя бы один раз.

```c
for (init_expr; guard_expr; next_expr) statement
```

Перед повторяющимся телом цикла вычисляется `init_expr`, затем цикл выполняется, пока `guard_expr` вычисляется в `true`, и перед очередной проверкой
условия вычисляется `next_expr`.

### Оператор switch

Оператор switch в языке C позволяет использовать в качестве аргумента только целочисленное значение.
Он имеет общий вид:

```c
switch (expression) statement
```

который на практике имеет обычно такую форму:

```c
switch (expression) {
case VAL1:
    break;
case VAL2:
    break;
default:
    break;
}
```

Забытый оператор `break` &mdash; это одна из типовых ошибок в C и C++ программах. Если `break` пропущен, исполнение после одной ветки switch
"провалится" на следующую ветку. Например:

```c
switch (x) {
case 0:
    printf("zero\n");
case 1:
    printf("one\n");
}
```

Если `x` равно 0, то на стандартный поток вывода будет напечатано:

```
zero
one
```

### Операторы передачи управления

Оператор `break` выходит из самого вложенного цикла или оператора `switch`.

Оператор `continue` переходит на следующую итерацию самого вложенного цикла.

Оператор `return` завершает выполнение текущей функции и возвращает указанное значение, если функция не `void`.

Оператор `goto L` передает управление на метку `L` в рамках текущей функции.

### Обработка ошибок

В языке C нет стандартного способа обработки ошибок. Отсутствует поддержка механизма исключений. Отсутствует специальный тип для ошибок,
отсутствует оператор `defer`. Поэтому в наших программах ошибки будут обрабатываться с помощью специальных возвращаемых значений
и оператора `goto`.

## Введение в стандартные средства для ввода и вывода

### Ввод-вывод символов

Первые практические задачи, которые вы будете выполнять, предполагают написание простых
программ, которые считывают входные данные со стандартного потока ввода и выводят результат
на стандартный поток вывода. При запуске такой программы в окне консоли входные данные
будут считываться с клавиатуры, а результат выводиться на экран.
Но ввод и/или вывод программы может перенаправляться, и источниками входной информации
для программы или потребителем результатов работы программы могут быть разные сущности,
причем для выполняющейся программы это перенаправление совершенно прозрачно.

Вводя исходные данные с клавиатуры и просматривая полученные результаты на экране, мы имеем дело, с *текстовой* информацией.
Такая трактовка оказывается очень простой и универсальной &mdash; именно такую модель ввода-вывода поддерживает стандартная библиотека C.
Текстовый ввод-вывод вне зависимости от того, откуда он исходит или куда направляется, имеет дело с потоком символов. 

**Текстовый поток** &mdash; это последовательность байт, предполагающая их визуальное представление в виде глифов,
отображаемых на экране монитора, бумаге или другом подобном носителе. Правила преобразования байтов в глифы называются кодировкой текстового файла.
Например, в кодировке ASCII байт со значением 48 преобразовывается в отображение на экране цифры 0.
Кроме отображаемых байт кодировка ASCII задает управляющие байты. Например, байт 10, который в коде программы на C записывается как `\n`
это управляющий символ, обозначающий конец визуальной строки текста при отображении потока байт на экране или другом подобном носителе.

При обработке текстовых потоков в ваших программах исходите из следующих требований и ограничений.
Текстовый поток, подаваемый на вход вашей программе, может не содержать символа `\n` в конце последней строки.
Однако текстовый поток, выводимый вашей программой, обязан содержать символ `\n` в конце последней строки.
Исключением является пустой вывод, то есть вывод, не содержащий ни одной строки, не должен и содержать `\n` (размер такого файла равен 0).
Кроме того, в условии задачи может быть явно оговорено, что финальный `\n` добавляться не должен, если входной поток его не содержит.

Хотя байт со значением 0 в файле вполне допустим, мы наложим дополнительное ограничение, что
входной текстовый поток никогда не будет содержать нулевого байта.
Выходной текстовый поток никогда не должен содержать нулевого байта, в противном случае вы получите Presentation error.

Стандартная библиотека включает несколько функций для чтения и записи одного символа.
Простейшие из них &mdash; `getchar` и `putchar`.
За одно обращение к `getchar` считывается следующий байт из стандартного потока ввода, и этот символ выдается в качестве результата. Так, после выполнения

```c
с = getchar();
```

переменная `c` содержит очередной байт из стандартного потока ввода. 

Обращение к `putchar` приводит к выводу одного байта на стандартный поток вывода. Так,

```c
putchar(c);
```

напечатает содержимое целой переменной `c` в виде символа, если стандартный поток вывода связан с терминалом.
Вызовы `putchar` и `printf` могут произвольным образом перемежаться.
Вывод будет формироваться в том же порядке, что и обращения к этим функциям.

### Декларации функций
По стандарту функции и макросы ввода-вывода символов имеют следующие прототипы:

```c
#include <stdio.h> 
    
int	getchar(void);		// equivalent to getc(stdin) 
int	getc(FILE *);		// possibly MACRO, equivalent to fgetc() 
int	fgetc(FILE *);	

int putchar(int);		// equivalent to putc(c,stdout).
int putc(int, FILE *);	// possibly MACRO, equivalent to fputc()
int fputc(int, FILE *);
```

Идентификаторы `stdin`, `stdout` и `stderr` имеют тип `FILE*` и обозначают, соответственно,
стандартный *входной поток*, стандартный *выходной поток* и стандартный *поток ошибок*.
Обычно стандартный входной поток ассоциирован с клавиатурой,
а стандартные выходной поток и поток ошибок &mdash; с экраном. Пользователь имеет возможность перенаправлять эти потоки:
например, можно соединить выход одной программы и вход другой, при этом сообщения об ошибках, выводимые в поток ошибок, будут выводиться на экран.

Для работы с символьными данными в C используется тип `char`, хотя могут использоваться и другие целые типы.
Встает вопрос: как отличить признак завершения ввода от прочих символов, поступающих на вход программе при вызове `getchar`?
Ответ &mdash; использовать такое значение, которое не будет совпадать ни с одним значением типа `char`.
Это значение называется `EOF` (англ. *end of file*, конец файла) &mdash; целая константа, определенная в `<stdio.h>` и имеющая тип `int`
В большинстве реализаций стандартной библиотеки эта константа равна -1, но для переносимости кода следует использовать имя `EOF`.

Напоминаем, что является ли тип `char` знаковым или нет &mdash; зависит от реализации (implementation defined).
На платформе x86/x64 тип `char` знаковый и, соответственно,
принимает значения в диапазоне [-128;127). На платформе ARM `char` &mdash; беззнаковый и принимает значения в диапазоне [0;255].
Но независимо от этого функция `getchar` возвращает считанный байт как целое число в диапазоне [0;255].
В случае невозможности прочитать очередной символ (например, потому что были прочитаны все символы или произошла какая-либо ошибка ввода-вывода) &mdash; возвращают `EOF`.

С этим связана одна из типовых ошибок использования функции `getchar`, а именно:

```c
char c = getchar();  // НЕПРАВИЛЬНО!
```

Функция `getchar` возвращает 256 различных значений байтов из входного потока **плюс дополнительное специальное значение EOF**.
Эти 257 разных значений никак не могут быть сохранены без потери информации в значении типа char (8 бит). Поэтому произойдет
потеря информации, и ваша программа будет либо зацикливаться, либо неправильно обрабатывать некоторые входные файлы. Правильный способ
использования `getchar` &mdash; присвоить результат в переменную с достаточным диапазоном. Обычно это `int`.
```c
int c = getchar();   // ПРАВИЛЬНО
```

С другой стороны, семейство функций `putchar`, `putc` и `fputc` рассматривают свой аргумент типа `int` как байт,
для этого делается конвертация к типу `unsigned char`, и записывают этот байт в выходной поток.
В случае успеха возвращают записанное значение, иначе возвращают `EOF`.

### Запись символов

Напомним, что в тексте программы символьные константы записываются с использованием одиночных кавычек: например буквы `'a'`, `'Y'`,
цифра `'0'` (не путать со значением константы `0`) или символ `'@'`.

Для написания специальных символов используются так называемые *escape-последовательности* (или *экранирование* символов).
При их написании используется символ обратной косой черты (backslash), например:

 * `'\n'` &mdash; символ перевода новой строки,
 * `'\r'` &mdash; символ возврата каретки,
 * `'\t'` &mdash; символ табуляции,
 * `'\b'` &mdash; символ забоя (backspace), 
 * `'\\'` &mdash; собственно, символ обратной косой черты,
 * `'\''` &mdash; одинарная кавычка (апостроф),
 * `'\"'` &mdash; двойная кавычка.

### Форматный ввод-вывод

Несколько библиотечных функций позволяют преобразовывать значения между внутренним представлением и текстовыми последовательностями,
которые могут быть прочитаны и записаны. Функции делятся на две группы:

 * Функции печати, объявленные в заголовочном файле `<stdio.h>`, преобразуют внутреннее представление в последовательности типа `char` и позволяют комбинировать последовательности для вывода. К этой группе относятся, например, функции `fprintf`, `printf`, `sprintf`, `snprintf`.
 * Функции сканирования, объявленные в `<stdio.h>`, преобразуют последовательности типа `char` и позволяют сканировать считываемые последовательности. К этой группе относятся функции `fscanf`, `scanf`, `sscanf`.
 
Одним из традиционно приписываемых недостатков форматного ввода-вывода C является его **типонебезопасность**, то есть возможность передать
аргументы для ввода-вывода, не соотвествующие по количеству или по типам переданной форматной строке.
Однако, все современные компиляторы языка C умеют распознавать использование функций форматного ввода-вывода, анализировать строку формата
и проверять ее соответствие фактически переденным параметрам. Для включения проверки форматного ввода-вывода в компиляторе GCC используется
опция `-Wformat`, которая активируется при указании опции `-Wall`. Поэтому еще раз напоминаем, что программы на языке C **должны**
компилироваться с опциями `-Wall -Werror`.

Чтобы проверка соответствия форматной строки функции форматного ввода-вывода параметрам функции стала возможна, форматная строка должна быть
константной и известна компилятору при обработке вызова функции. Поэтому мы запрещаем использовать функции форматного ввода-вывода
с форматной строкой, не известной на этапе компиляции.

### Задание форматирования

У любой из указанных функций в списке формальных аргументов имеется аргумент `format`, являющийся строкой формата, которая определяет требуемые преобразования.
Строка формата состоит из нуля или более спецификаций преобразования, литерального текста и пробельных символов
(например, символов табуляции или перевода новой строки).

Для задания форматирования используют символ процента и следующий за ним спецификатор:
например `%d` для работы с целыми числами, `%g` &mdash; для вещественных чисел одинарной точности `float`, `%lg` &mdash; для вещественных чисел двойной точности `double`.

### Форматированный вывод

По стандарту функции вывода имеют следующие прототипы:

```c
#include <stdio.h>
	
int printf(const char *format, ...); 
int fprintf(FILE *stream, const char *format, ...);	
int snprintf(char *s, size_t n, const char *format, ...);
int sprintf(char *s, const char *format, ...);
```

Функция `printf` осуществляет вывод результата в стандартный выходной поток `stdout`, функция `fprintf` &mdash; в указанный поток `stream`,
а функции `sprintf` и `snprintf` &mdash; в буфер `s`. Более подробно эти функции будут рассматриваться на другом занятии, посвященном работе со строками.

Функции возвращают в случае успеха число записанных байт либо отрицательное значение в случае ошибки.

Примеры использования функции `printf`:

```c
    printf("Hello, world\n"); // выводим строку как есть
    printf("The answer is: %d!\n", 42); // выводим строку The answer is: 42! и перевод строки
    printf("One says: %d%% of 100 is %d\n", 6, 13); // вывод: One says: 6% of 100 is 13
    printf("%x", 256); // вывод: 100
    printf("%08x", 512); // вывод: 00000200
    printf("%llu", -1LL); // вывод: 18446744073709551615
    printf("%f", 3.1415926535897932384626433832795028841971); // вывод: 3.141593
    printf("%.10g\n", 3.141592653589793238 * 100000000000.0); // вывод: 3.141592654e+11
```

Хотя чаще всего в качестве форматного аргумента функций форматного вывода передаются константные строки, вполне допустимо передавать и произвольные
строки, даже сформированные во время работы программы. В этом случае компилятор не может проверить соответствие формата фактическим параметрам и
вы используете функции форматного вывода на свой страх и риск. **Неправильное использование переменного форматного параметра может
приводить к уязвимостям в программе вплоть до того, что заданием специально подготовленной строки пользователь вашей программы
может заставить ее выполнить произвольный код.**

### Форматированный ввод

По стандарту функции ввода имеют следующие прототипы:

```c
#include <stdio.h>
	
int scanf(const char *format, ... );
int fscanf(FILE *stream, const char *format, ... );	
int sscanf(const char *s, const char *format, ... );
```

Функция `scanf` осуществляет ввод данных из стандартного выходного потока `stdin`, функция `fscanf` &mdash; из указанного потока `stream`,
а функция `sscanf` &mdash; из буфера `s`. Более подробно функция `sscanf` будет рассматриваться на другом занятии, посвященном работе со строками.
Каждая функция считывает байты, интерпретирует их согласно заданному формату `format` и сохраняет полученные результаты
используя указатели на переменные, полученные в своих аргументах.
Таким образом, ожидается, что в качестве аргументов функций форматного ввода, пользователь задает список указателей,
по которым будут сохраняться считанные значения. Несоответствие какого-либо аргумента форматной строке `format` приводит к неопределенному поведению. 

Большинство форматных преобразований чтения, например `%d`, `%f`, `%s` перед выполнением чтения пропускают пробельные символы.
Поэтому о пропуске пробельных символов отдельно заботиться не нужно. Исключение &mdash; `%c`.

В случае успеха функции возвращают число обработанных аргументов (успешно считанных, разобранных и сохраненных), или ноль,
если был неуспешным разбор самого первого аргумента. В остальных случаях (окончание данных во входном потоке или ошибка разбора очередного аргумента)
возвращается `EOF`, возможно с побочными эффектами.

Примеры использования функции `scanf`:

```c
    // в цикле считываем последовательность целых чисел разделенных пробельными символами до признака конца файла
    int a;
    while (scanf("%d", &a) == 1) {
    }

    // в цикле считываем последовательность пар целых чисел до признака конца файла
    int a, b;
    while (scanf("%d%d", &a, &b) == 2) {
    }

    // считываем long long
    long long x;
    int r = scanf("%lld", &x);

    // считываем double
    double d;
    int r = scanf("%lf", &d);
    // обратите внимание, что double выводится в printf с помощью %f, а считывается с помощью %lf

    // считываем пару шестнадцатеричных чисел, разделенных минусом, например, 100-1ff
    unsigned l, h;
    int r = scanf("%x-%x", &l, &h); // для примера выше получим результат l == 0x100, h == 0x1ff
```

При использовании функций форматного ввода нельзя игнорировать возвращаемое значение этих функций. Хотя язык C не принуждает
выполнять проверку возвращаемого значения, ее отсутствие мы считаем нарушением стиля кодирования.
