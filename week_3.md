# Указатели в C

Богатые возможности работы с указателями &mdash; отличительная черта языка C.
Они дают огромные возможности, часто труднодостижимые или вообще недостижимые
в других языках, но и являются постоянным источником ошибок как для начинающих,
так и для опытных программистов.
Более современные языки, нацеленные на нишу системного программирования, например Rust,
пытаются ограничить использование указателей, разрешая их только в unsafe-секциях.

## Неопределённое поведение

При исполнении программы возможны ситуации, когда операция не может быть выполнена
из-за того, что аргументы операции выходят за диапазон допустимых значений.
Например, при целочисленном делении делитель не может быть равен 0.
В повседневной терминологии мы говорим об ошибке при выполнении программы,
в некоторых языках в этой ситуации возникает ошибка выполнения программы,
которая приводит к аварийному завершению программы, а в некоторых языках
выбрасывается исключение, которое в программе можно поймать и обработать.

В языках C и C++ принят другой подход. Если при выполнении программы
при целочисленном делении делитель равен 0, программа попадает в ситуацию
«неопределённого поведения» (undefined behavior &mdash; UB).
Дальнейшее поведение программы никак не описывается стандартом языка
и может быть произвольным. Программа может завершиться аварийно, может зависнуть,
может продолжить выполнение, причём поведение программы при неопределённом поведении
может меняться от случая к случаю.
Такое на первый взгляд странное решение принято не из-за злонамеренности или
некомпетентности комитета по стандартизации языка, а по инженерным причинам. 

Во-первых, при компиляции программы обнаружить, что при выполнении программы
в некоторый момент времени произойдёт деление на 0, можно только в самых простых
случаях, когда в качестве делителя явно записана константа 0 или она
легко прослеживается по программе. Поэтому сделать так, чтобы ошибка деления на 0
всегда обнаруживалась при компиляции программы, невозможно. Деление на 0
выявляется только при выполнении программы.

Во-вторых, на разных процессорах инструкция целочисленного деления ведёт себя по-разному,
если делитель равен 0. На процессорах x86 (32- и 64-битных) попытка деления на 0
приводит к аппаратному исключению `#0`, которое перехватывается ядром операционной системы
и обычно вызывает аварийное завершение программы. На процессорах ARM инструкция
целочисленного деления при делителе 0 даёт результат 0, a на процессорах RiscV
&mdash; результат `0xFFFFFFFF` (-1). В любом случае программа продолжает выполнение.
Если процессор не поддерживает инструкцию деления (такие тоже бывают), деление
выполняется программно, и делитель 0 может обрабатываться ещё большим числом способов.
Если стандарт зафиксирует какое-либо поведение при делении на 0, то на платформах,
на которых деление на 0 обрабатывается по-другому, придётся реализовывать
дополнительные проверки на каждую операцию деления в программе.
Это противоречит требованию максимальной производительности
скомпилированного кода, поэтому комитет по стандартизации на это не пошёл.

С другой стороны, альтернативой неопределённому поведению
является _поведение, зависящее от реализации_ (implementation define behavior), то есть поведение,
фиксированное для конкретной реализации C. Каждая реализация
должна задокументировать поведение в таких ситуациях и
строго ему следовать. Часть случаев неопределённого поведения,
скорее всего, можно было бы отнести к поведению, зависящему от реализации,
и, в частности, деление на 0 тоже. Но с точки зрения стандартов C и C++,
деление на 0, как и многие другие ситуации, которые мы будем далее
рассматривать, являются неопределённым поведением.

Понятие неопределённого поведения не накладывает никаких ограничений,
как должен вести себя компилятор при компиляции программ, даже если
ситуация неопределённого поведения вполне очевидна. Но большинство
компиляторов работают по следующему принципу: поскольку ситуации
неопределённого поведения, как правило, нельзя выявить при компиляции,
и поскольку компилятор в случае неопределённого поведения может
вести себя произвольным образом, компиляторы предполагают,
что компилируемая программа не содержит неопределённое поведение.
Значит, если выполнение программы дошло до какого-то места программы,
ранее при выполнении неопределённое поведение не возникало.
Это предположение может использоваться при оптимизации программы.

Рассмотрим простой пример:

```c
#include <stdio.h>

int main()
{
    int x,y;
    int q;
    [[maybe_unused]] int r = scanf("%d%d", &x, &y);
    q = x / y;
    if (y == 0) {
        printf("y is zero!\n");
    }
    printf("%d\n", q);
}
```

В этой программе сначала выполняется деление, а потом проверка делителя на 0.
При компиляции проверки на 0 компилятор делает предположение, что если
выполнение программы дошло до этой строки, то ранее никакого неопределённого
поведения не возникло. Следовательно, переменная `y` не равна 0,
и поэтому проверку условия и печать можно из программы удалить.
Действительно, если мы скомпилируем программу компилятором clang на ARM или RiscV без оптимизаций:

```bash
clang 1.c -o1
```

и введем при запуске '1 0', то получим в результате один вывод:

```
y is zero!
0
```

Если мы скомпилируем программу с оптимизациями:

```bash
clang 1.c -O2 -o1
```

вывод будет другим:

```
0
```

Компилятор gcc более осторожен при оптимизациях, построенных на предположении об отсутствии неопределённого
поведения, а компилятор clang более агрессивен. Но в любом случае ваша программа
никогда не должна попадать в ситуацию неопределённого поведения!

В стандарте языка C достаточно много ситуаций отмечены как неопределённое поведение,
а в стандарте языка C++ их ещё больше. Главная опастность неопределенного поведения в том,
что нельзя полагаться на то, что поведение компилятора или среды исполнения останется
неизменным при переходе на другую платформу или новую версию компилятора. Например,
если программа написана из предположения, что при делении на 0 возникает аппаратное
исключение, и программа перехватывает и обрабатывает это исключение, то при
запуске этой же программы под ARM программа будет работать неправильно,
а в какой-то момент и на x86 компилятор может так соптимизировать программу, что она
«сломается».

Существуют различные инструменты, которые помогают диагностировать неопределённое поведение
при работе программы. Это различные санитайзеры, valgrind и другие. Эти инструменты пригодны
для запуска в тестовом окружении, но в «промышленном» окружении их, как правило,
использовать нельзя по разным причинам. Поэтому ещё раз подчеркнём важность тщательного тестирования
программы перед запуском её в промышленном окружении. В дальнейшем мы покажем использование
санитайзеров в разработке программы.

## Указатели 101

Указательный тип обозначается звездочкой '`*`' **перед именем переменной**. То есть, конструкция

```c
int * a, b;
```

определяет переменную `a` типа указателя на `int` (`int*`) и переменную `b` типа `int`.
Поэтому символ '`*`' принято писать рядом с именем переменной, а не рядом с типом.
Кроме того, каждую переменную указательного типа определяйте отдельно.
Сразу при объявлении переменной указательного типа инициализируйте ее нулевым указателем.

Так неправильно:

```c
int* a, * b;
```

а так правильно:

```c
int *a = NULL;
int *b = NULL;
```

Указательный тип имеет специальное значение, которое гарантированно не указывает на
объект. Оно обозначается как `0`, `NULL` или `nullptr` (в C23). Оно называется «нулевой указатель»
(null pointer). Битовое представление нулевого указателя может содержать ненулевые биты,
хотя на всех распространённых платформах нулевой указатель побитово равен нулевому значению.
Если значение указательного типа используется в контексте, где требуется
булевское значение, нулевой указатель преобразуется в `false`, а любой другой указатель
преобразуется в `true`.

Любые два указателя одного типа можно сравнивать на равенство и неравенство.
Любой указатель можно сравнивать на равенство или неравенство с нулевым указателем `NULL`.

Указательный тип может быть дополнен квалификатором `const`.
Например, `const int *` или `int const *` &mdash; это указатель на
переменную типа `int`, которую нельзя модифицировать.
`int * const` &mdash; это указатель, который нельзя модифицировать,
на переменную типа `int`, которую можно модифицировать.
`int * const *` &mdash; это указатель, который можно модифицировать,
на указатель, который нельзя модифицировать, на переменную типа `int`,
которую можно модифицировать.

Чтобы переменная указательного типа начала указывать на существующий объект,
например на переменную, используется операция _взятия адреса_ `&`.
Чтобы получить значение переменной, на которую указывает указатель,
его нужно разыменовать с помощью _операции разыменования_ `*`.

Например,

```c
int a = 10, b = 20;
int *c = &a;
printf("%d\n", *c);  // выводим 10
```

Разыменование нулевого указателя, или неинициализированной локальной переменной
указательного типа, или указателя, указывающего на переменную, у которой
закончилось время жизни, &mdash; всё это неопределённое поведение.

```c
int *a = NULL;
int *b;
int *c;
{
    int d = 10;
    c = &d;
}
printf("%d\n", *a); // UB - разыменование нулевого указателя
printf("%d\n", *b); // UB - разыменование неинициализированной локальной переменной
printf("%d\n", *c); // UB - разыменование указателя на уничтоженную переменную
```

В C передача указателя на переменную в функцию используется, чтобы функция могла
модифицировать переменную, не локализованную в функции. Например:

```c
void swap(int *pa, int *pb)
{
    int t = *pa;
    *pa = *pb;
    *pb = t;
}

int main()
{
    int a = 100;
    int b = 200;
    swap(&a, &b);
    printf("%d\n%d\n", a, b);
}
```

Если функция принимает в качестве параметра указатель, но функция не модифицирует
переменную, на которую он указывает, а только использует её значение,
параметр лучше передавать как константный указатель; это является дополнительной
полезной информацией для человека и компилятора в точке вызова функции. Например:

```c
void write(const int *x)
{
    printf("value: %d\n", *x);
}
```

## Strict aliasing rule

Два указателя могут указывать на одну и ту же переменную,
например:

```c
int a = 100;
int *b = &a;
int *c = b;
```

В этом примере и указатель `b`, и указатель `c` указывают на переменую `a`.
Если два и более указателя указывают на одну переменную, точнее,
на одно место в памяти, где располагается переменная, говорят, что
эти два указателя являются _алиасами_ (синонимами) переменной. Если в программе есть
два указателя, например `int *p` и `int *q`, компилятору важно знать,
могут ли эти указатели указывать на одну и ту же переменную. Если
компилятор может доказать, что `p` и `q` никогда не указывают
на одну переменную, это открывает простор для многих оптимизаций кода.
К сожалению, доказать утверждение о том, что переменная не может быть
алиасом другой переменной, можно только в простых случаях.
Поэтому, чтобы позволить компилятору выполнять больше оптимизаций кода
в языках C и C++ действует правило _строгого алиасинга_ (strict aliasing rule):
если два указателя с несовместными типами указывают по факту на одну и ту же
переменную &mdash; это неопределённое поведение.

Два типа совместны, если они отличаются только знаковостью (например,
`int` и `unsigned int`), либо один или оба из них &mdash;
варианты типа  `char`. Поэтому, например, если переменная `int *`
указывает на переменную типа `float, это неопределённое поведение.
Отсюда следует, что компилятор может предполагать, что указатель `int*` никогда не может
указывать не переменную типа `float`.

Рассмотрим пример.

```c
#include <stdio.h>
#include <stdint.h>

int *convert(float *p)
{
    return (int*) (intptr_t) p;
}

int main()
{
    float v1 = 100;
    int *p2 = convert(&v1);
    v1 = 200;
    *p2 = 0;  // переменная v1 перезаписывается нулём - UB
    printf("%f\n", v1);
}
```

Функция `convert` преобразует указатель на `float` в указатель на `int`.
Получается, что переменная `p2` указывает на переменную типа `float`,
что является нарушением strict aliasing rule и, соответственно,
неопределённым поведением. Поэтому компилятор при обработке функции `main`
имеет право предполагать, что на переменную `v1` нет указателей.

Если скомпилировать программу компилятором `clang` без оптимизаций,
программа ожидаемо выведет 0.

Но если включить оптимизацию, программа выведет 200. Компилятор считает,
что `p2` не указывает на `v1`, поэтому может заменить переменную `v1`
на константу 200, которую она получила при присваивании.

## Константы в C

Под константами в программе мы понимаем значения или выражения,
которые полностью могут быть вычислены компилятором на этапе
компиляции программы. В некоторых конструкциях языка могут быть
использованы только константы или константные выражения.

Обратите внимание, что глобальная переменная, определенная с квалификатором `const`,
не является определением константы компиляции. Это неправильный фрагмент определения глобального массива:

```c
const int SIZE = 16;
int glob[SIZE];
```

Хотя и gcc, и clang такое поддерживают, но как расширение, позаимствованное из C++. Ключевое слово `const`
в C всегда используется для определения объектов, которые размещаются в памяти, недоступной для записи.
Недоступность для записи может быть и «логическая», то есть мы хотим запретить функции модифицировать
параметр, передаваемый как указатель, хотя вне функции эта переменная может быть модифицирована.
Недоступность для записи может быть и «физическая», то есть переменная размещается в памяти,
которую нельзя модифицировать из-за ограничений процессора, компьютера или операционной системы. 

Традиционный способ определения констант в языке C &mdash; с помощью директивы препроцессора `#define`:

```c
#define SIZE 16
```

Замена идентификатора `SIZE` на константу 16 выполняется препроцессором C,
и эта замена не учитывает структуру программы: определение структур данных,
вложенность блоков функций и тому подобное. Использование `#define`
считается устаревшим способом определения констант, поэтому директивы препроцессора мы использовать не будем.

Другой способ, хотя и корявый, но использующий средства самого языка, а не препроцессора, &mdash; это
анонимный перечислимый тип с одним элементом.

```c
enum { SIZE = 16 };
```

Константа `SIZE` является константой периода компиляции и может использоваться в константном контексте.
Формально она имеет тип анонимного перечисления, но неявно преобразовывается к целым типам.

В стандарте C23 добавили `constexpr` для определения именованных констант.

```c++
constexpr int SIZE = 16;
```

Эта форма предпочтительна, но, если C23 недоступен, используйте форму с `enum`.

## Структурный тип

Пример определения структуры приведён ниже.

```c
struct MyStruct
{
    int a, b;
    int c;
    double f;
};
```

Здесь определяется структура с тегом `MyStruct`, содержащая пять полей.
Тег структуры в C не может использоваться как тип самостоятельно,
требуется его использование вместе с ключевым словом `struct`. Например,

```c
struct MyStruct v;
struct MyStruct *p;  // указатель на структуру
```

Чтобы использовать имя типа без указания ключевого слова `struct`
можно определить `typedef` алиас на тип структуры, например

```c
typedef struct MyStruct MyStruct;
```

Тогда далее можно использовать идентификатор `MyStruct` для использования типа структуры.

Возможно _опережающее объявление_ (forward declaration) структурного типа.

```c
struct SomeStruct;
```

Далее в программе тип `struct SomeStruct` можно использовать, если для использования
компилятору не требуется знать размер типа. Опережающие объявления используются
для определения структур данных, которые содержат указатели друг на друга,
например списков или деревьев, а также для объявления функций,
которые принимают или возвращают указатели на этот тип. Чтобы присваивать
указатели, компилятору не требуется знание внутреннего устройства типа,
на который они указывают, поэтому компилятору достаточно опережающего объявления.

Структурный тип не может быть пустым, это **неопределённое поведение**.

```c
struct Empty // empty structure - undefined behavior
{
};
```

Компиляторы gcc и clang позволяют определять структуры без полей,
и размер структуры в этом случае равен 0. Но поскольку это &mdash;
неопределённое поведение, полагаться на это нельзя.

Для сравнения, в языке C++ структуры без полей разрешены, но размер
такой структуры равен 1.

### Инициализация переменных структурного типа

При определении переменная структурного типа может быть инициализирована.
Значения, которые присваиваются полям, записываются в фигурных скобках.
Например,

```c
struct MyStruct v1 = {};               // все поля инициализируются нулем
struct MyStruct v2 = { 1, 2, 3, 4.0 }; // поля инициализируются по порядку
struct MyStruct v3 = { 1, 2 };         // поля c и f инициализируются нулями
struct MyStruct v4 = { .b = 2 };       // поле b инициализируется явно, остальные - нулями
```

Если переменная не инициализирована явно, но является глобальной или статической,
все поля инициализируются нулями. Но если переменная &mdash; локальная в функции,
неинициализированная переменная заполняется какими-то _недетерминированными_ (indeterminate)
значениями (скорее всего, это какие-то данные, оставшиеся в памяти после работы других функций).
Если для некоторого типа существуют значения, чтение которых приводит к аппаратному
исключению, то в этом случае в программе на C возникает неопределённое поведение.
Впрочем, у популярных процессорных архитектур таких типов нет. Поэтому в программе на C
простое чтение значения неинициализированной локальной переменной не вызывает
неопределённого поведения. Но в языке C++ любое чтение значения неинициализированной
переменной (за некоторыми исключениями для `char`-типов) &mdash; уже неопределённое поведение.

В некоторых случаях компиляторы C и C++ диагностируют использование
неинициализированной переменной, для этого должна быть включена опция оптимизации
программы `-O2`. Более точную диагностику во время работы программы обеспечивают
санитайзеры или valgrind.

### Доступ к полю структурного типа

Для доступа к полю структуры, если со структурой мы работаем как
со значением, используется операция `.` (точка). Например,
для структуры `MyStruct`

```c
    struct MyStruct v;

    v.a = v.c + v.b;
```

Но если мы работаем со структурой через указатель, используется
операция `->`. Например,

```c
    struct MyStruct *p = &v;
    p->a = p->c + p->b;
```

Для такого разделения на две разных операции нет никаких причин,
почти во всех языках для доступа к полю и по значению, и по указателю
достаточно единственной операции `.`. Но две различных
операции существуют в языке с самого начала, и так и останется.

### Размер структуры, выравнивания

Рассмотрим структуру

```c
struct A
{
    char f1;
    long long f2;
    char f3;
}
```

Размер типа `char` &mdash; 1 байт, размер типа `long long` &mdash; 8 байт.
Но если мы напечатаем размер структуры

```
    printf("%zu\n", sizeof(struct A));
```

мы получим 24 вместо 10. На что ушло ещё 14 байтов?

Дело в том, что при размещении переменных любого типа в памяти должны быть выполнены
требования по выравниванию значений типа. Так, на 64-битных платформах значения типа `long long`
имеют выравнивание 8. Это значит, что смещение от начала структуры, по которому размещается
поле типа `long long`, должно быть кратно 8. В нашем примере поле `f1` имеет размер 1,
поэтому следующее поле должно иметь смещение от начала структуры не меньше 1.
Поскольку требуется выравнивание 8, компилятор разместит поле `f2` по смещению 8.
Семь байт между полями `f1` и `f2` не будут использоваться. Неиспользуемое
пространство между полями
_выравниванием_ (padding). Далее поле `f2` заканчивается по смещению 16,
и поле `f3` располагается непосредственно за ним без выравнивания. Поле `f3` заканчивается на
смещении 17. Но по этому смещению мы не сможем разместить следующий объект типа `struct A`,
потому что тогда выравнивания внутри структуры окажутся неправильными. Поэтому
необходимо после поля `f3` добавить ещё семь байтов выравнивания, чтобы
итоговый размер структуры стал равен 24, и непосредственно следующая за ней структура `struct A`
будет иметь правильные выравнивания внутри. Таким образом, размер структуры должен быть кратен
максимальному выравниванию поля внутри структуры. Выравнивание структуры равно
максимальному выравниванию поля внутри неё.

Выведем информацию о размещении полей структуры:

```c
#include <stdio.h>
#include <stddef.h>

struct A
{
    char f1;
    long long f2;
    char f3;
};

int main()
{
    printf("%zu\n", sizeof(struct A));
    printf("%zu\n", offsetof(struct A, f1));
    printf("%zu\n", offsetof(struct A, f2));
    printf("%zu\n", offsetof(struct A, f3));
}
```

На стандартном потоке вывода получим

```
24
0
8
16
```

Выравниванием полей структуры и переменных можно управлять. Модифицируем структуру следующим образом:

```c
struct A
{
    char f1;
    _Alignas(16) long long f2;
    char f3;
};
```

Конструкция `_Alignas(16)` задает, что выравнивание поля `f2` должно быть 16. Выравнивание должно быть степенью двойки
и не может быть меньше «натурального» выравнивания соответствующего типа данных.
Тогда на стандартном потоке вывода получим

```
32
0
16
24
```

Компилятор всегда размещает переменные и поля структур, выполняя требования по выравниванию, но если получилось сделать так, что указатель указывает на данные, выровненные неправильно,
например, тип `long long ` оказался расположенным по смещению 1, то обращение к невыровненным данным
&mdash; это **неопределённое поведение**.

На примере типа `struct A` видно, что порядок размещения полей в структуре может влиять на ее размер.
Поменяем порядок размещения полей следующим образом:

```c
struct A_good
{
    long long f2;
    char f1;
    char f3;
};
```

Размер структуры `struct A_good` равен 16, то есть мы уменьшили размер на треть! То есть, чтобы структура
имела минимальный размер, её поля должны размещаться в порядке уменьшения требований
к выравниванию. Поля типа `long long` &mdash; в начале, поля типа `int` за ними, поля типа `char` в конце.
Требования к выравниванию для разных типов данных для типичной 64-битной платформы (x86, ARM, RiscV)
приведены в таблице ниже.

| Тип данных | Выравнивание |
| - | - |
| `_Bool`, `char` | 1 |
| `short` | 2 |
| `int`, `float` | 4 |
| `long`, `long long`, `double` | 8 |
| `T*` (указатели) | 8 |
| `_int128` | 8 |

## Массивы

Одномерные массивы определяются следующим образом:

```c
int arr1[32];
```

Здесь объявлен массив из 32 значений типа `int`. Если массив глобальный, его размер должен быть константным выражением,
то есть быть известен на этапе компиляции.

Если массив локальный, язык C позволяет определять _массив переменного размера_ (variable length array &mdash; VLA),
например так:

```c
    int n;
    scanf("%d", &n);
    int arr2[n];
```

но использование таких массивов требует крайней аккуратности с размером массива, кроме того, массивы переменного
размера не поддерживаются в языке C++. Поэтому мы **запрещаем использование массивов переменного размера!**
Мы всегда будем использовать массивы только фиксированного размера.

Массив, как глобальный, так и локальный, может быть инициализирован при определении:

```c
    int arr1[8] = {};                   // массив инициализируется нулями
    int arr2[8] = { 1, 2, 3, 4 };       // первые четыре элемента проинициализированы явно, остальные - нули
    int arr3[8] = { [1] = 2, [3] = 3 }; // элементы с индексами 1 и 3 проинициализированы явно, остальные - нули
```

Если определение массива содержит инициализатор, то его размер можно опускать. Он будет определён из инициализатора:

```c
    int arr4[] = { 10, 20 }; // размер массива - 2
```

Массивы нулевого размера запрещены (ошибка компиляции), кроме случая, когда такой массив является
последним полем в структуре.
Размер массива равен произведению количества элементов на размер одного элемента.
Поэтому, если `arr` &mdash; массив, то количество элементов в нём можно вычислить с помощью
выражения `sizeof(arr)/sizeof(arr[0])`. **Внимание, эта формула не работает для указателей!**

В памяти элементы массива располагаются последовательно без пропусков между элементами. В массиве
с элементами типа `int` элемент с индексом 0 находится по смещению 0, элемент с индексом 1 &mdash; по
смещению 4, с индексом 2 &mdash; по смещению 8 и так далее.

### Индексация элементов массива

Массив индексируется обычным образом: выражением в квадратных скобках. Если индекс выходит за пределы
массива, такая операция доступа к элементу массива даёт неопределённое поведение.
Диапазон допустимых индексов в массиве &mdash; от 0 включительно до количества элементов в массиве минус 1.
Стандартный цикл прохода по всем элементам массива записывается так:

```c
    //int arr[N];
    for (int i = 0; i < N; ++i) {
        // операции с arr[i]
    }
```

Строго говоря, использование переменной типа `int` здесь некорректно, так как массив может содержать
больше чем $2^{31}-1$ элемент, то есть допустимые индексы будут непредставимы положительным
знаковым 32-битным числом. В этом случае при выполнении цикла возникнет неопределённое поведение.
Правильный способ &mdash; использовать для итерации по массиву тип `size_t` или тип `ssize_t`.

```c
    for (size_t i = 0; i < N; ++i) {
        // операции с arr[i]
    }
```

Такой цикл будет корректным для любого количества элементов в массиве. Но тип `size_t` &mdash; беззнаковый тип,
и наивный проход по массиву в обратном направлении окажется неправильным:

```c
    for (size_t i = N - 1; i >= 0; --i) { // Цикл никогда не закончится!!!
        // работаем с arr[i]
    }
```

Правильный способ обратного прохода по массиву с использованием беззнакового индекса &mdash;
увеличить его на 1:

```c
    for (size_t i = N; i > 0; --i) {
        // работаем с arr[i-1]
    }
```

### Важные целочисленные типы данных

При работе с индексами массива и с указательной арифметикой, которую рассмотрим чуть ниже, используются
специальные целочисленные типы данных. Они определены в стандартной библиотеке как алиасы на
встроенные типы, которые равны по размеру указательному типу, но имеют разную знаковость.

Тип `size_t` &mdash; важнейший из них. Операция `sizeof`, встроенная в язык, даёт значение этого типа.
Фактически тип `size_t` является частью языка, хотя формально определяется в заголовочном
файле `<stddef.h>`. Тип `size_t` &mdash; беззнаковый, на POSIX-совместимых платформах
он является алиасом типа `unsigned long` и на 64-битных платформах имеет размер 8, а на 32-битных &mdash;
размер 4. Язык C гарантирует, что размер любого объекта в программе является представимым в типе `size_t`.

Тип `ssize_t` &mdash; это знаковый тип, имеющий такой же размер, что и `size_t`. Возможно,
он избыточен, так как существует тип `ptrdiff_t`, но стандартная библиотека его определяет
для использования в случаях, когда системный вызов возвращает
размер, но может возвращать и отрицательное значение, сигнализируя об ошибке.

Тип `ptrdiff_t` &mdash; это знаковый тип. Если `i` и `j` &mdash; это два индекса элементов
**одного** массива, то гарантируется, что разность между ними, которая может быть
как положительной, так и отрицательной, представима значением типа `ptrdiff_t`.
На POSIX-совместимых платформах это алиас для типа `long`.
Отсюда следует, что на 32-битных платформах разность двух индексов должна
быть представима 32-битным знаковым числом. Если мы возьмем минимальный индекс в массиве 0,
то максимальный индекс в массиве должен быть меньше $2^{31}-1$. Отсюда следует,
что размер любого объекта в 32-битной программе должен быть меньше 2GiB.
А отсюда следует, что нет необходимости делать `size_t` беззнаковым, так как все допустимые
размеры прекрасно представимы и знаковым значением. Беззнаковость типа `size_t` &mdash; это
один из источников ошибок в программах на C и C++.

Тип `intptr_t` &mdash; это знаковый тип достаточной битности, чтобы без потерь сохранить
битовое значение указателя. Гарантируется, что преобразование из типа указателя в тип `intptr_t`
и обратно сохранит битовое представления указательного значения.
Тип `uintptr_t` аналогичен, только беззнаковый. Казалось бы, что для представления
значений указателя как целого числа достаточно типов `size_t` или `ssize_t`, но
стандартная библиотека C определяет эти типы для большей ясности в программе,
чтобы было понятно, когда мы храним размеры, а когда &mdash; битовые представления
указателя.

### Арифметика указателей

Арифметику указателей проще всего определить в терминах операций над индексами
одного массива.

Итак, пусть дан массив

```c
T arr[N];
```

здесь `T` &mdash; некоторый тип массива, `N` &mdash; количество элементов в нём.
Сразу заметим, что размер массива, то есть `sizeof(T) * N` должен быть
представим в типе `ssize_t` или `ptrdiff_t`.

Возьмем два любых индекса `i` и `j`, удовлетворяющих условию $0 \leq i,j \leq N$.
Обратите внимание, что индексы могут принимать значение, равное количеству элементов в массиве.
Тем не менее обращаться по такому индексу нельзя. Теперь пусть два указателя
`p` и `q` определены так:

```c
T *p = &arr[i];
T *q = &arr[j];
```

Если `i` или `j` не удовлетворяет ограничению выше, операция взятия адреса
даёт неопределённое поведение. Как мы видим, указатель на элемент
массива может указывать как на существующий элемент массива, так и на место,
непосредственно следующее за концом массива. Гарантируется, что это
будет корректное значение указателя. Однако разыменовывать такой указатель нельзя
&mdash; неопределённое поведение.

Два указателя `p` и `q` можно сравнивать друг с другом. Поддерживаются все шесть
операций сравнения: `==`, `!=`, `>`, `>=`, `<`, `<=`. Сравнение указателей
эквивалентно соответствующей операции сравнения индексов, от которых взяты указатели.
То есть `p OP q` это то же самое, что `i OP j`.

Можно вычислять разность двух указателей. `p - q` это то же самое,
что разность двух индексов, рассматриваемых как знаковые значения, то есть
`p - q == (ptrdiff_t) i - (ptrdiff_t) j`. Разность двух указателей
имеет тип `ptrdiff_t` и может быть как положительной, так и отрицательной.

К указателю можно прибавлять или вычитать знаковое число. Пусть `p`
определён как показано выше, и выполняется операция `p OP x`,
где OP &mdash; это `+` или `-`. Тогда индекс `k = i OP x`
должен удовлетворять ограничению на индексы, иначе &mdash; неопределённое поведение.
Соответственно, результат операции получается равным `p OP x == &arr[i OP x]`.
Из определения сложения и вычитания следуют определения операций `+=` и `-=`,
а также `++` и `--` как префиксных, так и постфиксных.

Вот некоторые примеры использования указательной арифметики:

```c
int arr[N];

int *p1 = &arr[0]; // p1 указывает на начало массива
--p1;              // undefined behavior

int *p2 = &arr[0];
p2 += N;           // ok, p указывает на место сразу за концом массива
++p2;              // undefined behavior

int *p3 = &arr[0] + N;
*p3;               // undefined behavior

int *p4 = &arr[3]; // ok, если N > 3
int *p5 = p4 - 2;  // &arr[1]
int *p6 = p4 + 4;  // ok, если N > 7
```

Если в выражении используется имя массива, оно неявно приводится к указателю на начало массива,
то есть вместо `&arr[0]` можно написать просто `arr`.

Для указательных типов определена операция индексации. Если `p` &mdash; указатель,
то `p[i]` &mdash; это то же самое, что `*(p + i)`, а `&p[i]` &mdash; то же самое, что `p + i`.
Поэтому при индексации указателя индекс может быть отрицательным, например
`p[-1]` &mdash; это элемент массива, предшествующий тому, на который указывает `p`.

В модели памяти языка C объект любого типа &mdash; от встроенного до массивов, структур и их композиций &mdash;
находится в области памяти, представляемой в виде массива элементов типа `char` или `unsigned char`.
Поэтому можно получить указатель на какой-то элемент объекта, преобразовать его к типу
`unsigned char *` и использовать адресную арифметику при условии, что указатель не выходит
за пределы объекта.

В C можно взять указатель на одиночную переменную, можно взять указатель на начало массива.

```c
int x;
int a[16];
int *p = &x;
int *q = a;
```

Переменные `p` и `q` имеют один и тот же тип `int *`. По значению указательного типа невозможно
определить, указывает ли оно на одиночную переменную, либо на начало или какую-то другую позицию массива.
Вместе с указателем не хранится длина массива, поэтому длину массива приходится хранить отдельно
и передавать в функции тоже отдельно от указателя на обрабатываемые данные.

### Тип void*

Тип `void*` введён, чтобы можно было передавать в качестве параметров, возвращать из функций и
хранить в переменных указатель без спецификации типа, на которые он указывает. В одном месте программы
в нём могут храниться значения типа `int*`, в другом &mdash; `void*` и так далее.
Переменной типа `void*` могут без явного преобразования типов присваиваться любые указательные значения.
И наоборот, в языке C любой указательной переменной могут без явного преобразования типов присваиваться
значения типа `void*`. В языке C++ неявное преобразование `void* -> T*` запрещено.
Для типа `void*` не поддерживается арифметика указателей, и указатели этого типа нельзя разыменовывать.

Указатели типа `void*` могут быть алиасами любых переменных.

### Многомерные массивы

Двухмерные массивы определяются следующим образом:

```c
int matr[3][2];
```

Расшифровать определение можно так: `matr` &mdash; это массив из 3 элементов, каждый элемент которого
&mdash; это массив из 2 элементов типа `int`. Первый индекс обычно называется _индекс строки_,
а второй индекс &mdash; _индекс столбца_. Говорят, что двухмерный массив хранится по строкам,
то есть при перемещении по области памяти быстрее всего изменяется самый правый индекс,
как показано ниже.

```
matr[0][0], matr[0][1], matr[1][0], matr[1][1], matr[2][0], matr[2][1]
```

Если дан двухмерный массив

```c
int matr[M][N];
```

можно получить адрес его начала

```c
int *p = &matr[0][0];
```

и работать с двухмерным массивом как с одномерным: `matr[i][j]` &mdash; это то же
самое, что `p[i*N + j]`.

Двухмерный массив можно инициализировать вложенными инициализаторами.

```c
int matr[3][2] =
{
    { 1, 2 },
    { 3, 4 },
    { 5, 6 },
};
```

Массивы размерности 3 и больше определяются аналогично. Например,

```c
int m[L][M][N];
int *p = &m[0][0][0];

m[i][j][k] == p[i*M*N + j*N + k]
```

Обратите внимание, что самый левый размер многомерного массива не используется
при вычислении положения элемента в памяти.

### Передача массивов в функции

Функции в C не могут возвращать массивы.

Функции в C не могут принимать массивы в качестве параметра. Вместо этого
передаётся указатель.

Запись

```c
void f(int a[]);
```

или запись

```c
void f(int a[N]);
```

эквивалентна записи

```c
void f(int *a);
```

При вызове этой функции, если в качестве аргумента передать имя массива, оно неявно
преобразовывается в указатель на начало массива, то есть вызов `f(arr)` эквивалентен
`f(&arr[0])`.

При передаче многомерного массива в качестве параметра нужно указывать все размеры,
кроме самого правого, но размеры массива могут передаваться в качестве параметра.

```c
void f(int M, int N, int matr[][M][N]);
```

## Строки в C

В языке C нет специального строкового типа. Строка &mdash; это последовательность элементов
типа `char`, завершающаяся нулевым байтом. Нулевой байт не может находиться в середине строки.
Строковые литералы в программе записываются в кавычках.
Например, строка `"Hello"` &mdash; это последовательность 6 байт `'H'`, `'e'`, `'l'`, `'l'`, `'o'`, `0`. Нулевой байт учитывается в размере строки, то есть
`sizeof("Hello") == 6`. Строковой литерал имеет тип `const char *`.

В C существуют ещё _широкие строки_ (wide strings), но мы их рассматривать не будем.

Строки хранятся в массивах элементов типа `char`. Поскольку строки не хранят явную длину, а используют
специальный байт-терминатор `0`, чтобы передать уже готовую строку на обработку в функцию
достаточно единственного параметра типа `const char *`. Так устроена стандартная библиотека C
и интерфейс системных вызовов. В этом случае подразумевается, что строка размещена
в массиве достаточного размера.

Рассмотрим присваивание

```c
const char *str = "Hello";
```

Здесь `str` &mdash; это указатель, которому присваивается адрес начала массива `char[]`, хранящего байты строки.
Поэтому такое присваивание является сокращением следующей конструкции:

```c
static const char str_arr[] = "Hello"; // специальная форма инициализации массива char [6] последовательностью байт строки
const char *str = str_arr;
```

Массив `str_arr` имеет длину 6 и размещается в секции констант, которая защищается от записи в неё
механизмом защиты памяти.

Для хранения неконстантных строк, которые можно модифицировать в ходе работы программы,
также используются массивы `char []` выделенные в глобальной, локальной или динамической памяти.

Например, в функции можно определить массив для хранения строки:

```c
void f()
{
    char buf[64] = "Hello";
}
```

Здесь определяется локальная переменная `buf` &mdash; массив длины 64 элементов типа `char`.
При каждом входе в функцию `f` будет выделяться 64 байта под строку, а в первые 6 байт
строки будут записаны байты строки, включая завершающий нулевой байт.
Поскольку для строки требуется завершающий нулевой байт, максимальная длина строки, которую
можно разместить в этой переменной, равна 63. Программист должен сам следить за тем,
чтобы строки размещались в массивах достаточной длины. Ошибка переполнения буфера, то есть
ситуация, когда в силу недостаточного контроля длины строки строка не уместилась
в отведённый для неё буфер и вышла за его пределы, может привести к катастрофическим последствиям
при работе программы, и это одна из классических ошибок, из-за которой язык C считается
«небезопасным» языком.

Ещё одной ловушкой при программировании на C и C++ является то, что знаковость типа `char`
зависит от реализации, и на платформе Intel x86 тип `char` знаковый. Допустимые значения
типа `char` находятся в диапазоне [-128; 127]. В положительные значения попадают
коды символов кодовой таблицы ASCII, то есть цифры, заглавные и строчные латинские буквы
и различные знаки пунктуации, но, например, последовательности байтов, задающие символы
кириллицы во всех кодировках, в том числе UTF-8, имеют отрицательные целые значения.
Если требуется ручная обработка строк, это неудобно и очень часто приводит к ошибкам.
Поэтому при обработке байтов строк приходится их
преобразовывать к типу `unsigned char`, либо сразу использовать тип
`unsigned char *` для хранения и передачи строк в программе, каждый раз сталкиваясь
с необходимостью преобразования типа указателя при использовании функций стандартной
библиотеки. Чтобы компилятор не выдавал предупреждения каждый раз, когда указатель типа `unsigned char *`
передаётся в качестве параметра в функцию стандартной библиотеки, ожидающую тип `char *`,
полезно в опции командной строки компилятора добавить `-Wno-pointer-sign`.

Таков путь.

### Функции стандартной библиотеки для работы со строками

В стандартном заголовочном файле `string.h` определены функции работы со строками.
Современные компиляторы знают семантику этих функций и пытаются оптимизировать
их использование в программе.

Длину строки можно получить с помощью функции `strlen`:

```c
size_t strlen(const char *s);
```

Возвращается длина строки без учета завершающего строку нулевого байта-терминатора.
Функция работает за линейное время от длины строки, поскольку требуется пройти по
строке до первого нулевого байта. Поэтому следующий фрагмент кода содержит грубую
ошибку:

```c
for (size_t i = 0; i < strlen(s); ++i) { // ОЧЕНЬ ПЛОХО!
    count += s[i] == '0';
}
```

В этом цикле функция `strlen` вызывается на каждой итерации, и на каждой итерации
проходит по всей строке. В итоге время работы этого фрагмента программы
становится квадратичным, а не линейным. Компиляторы в некоторых простых ситуациях
могут оптимизировать этот фрагмент, чтобы `strlen` вызывался только один раз,
но не обязаны это делать. Правильно писать так:

```c
for (size_t len = strlen(s), i = 0; i < len; ++i) {
    count += s[i] == '0';
}
```

В этом фрагменте `strlen` будет вычислен один раз.

Две строки можно сравнить с помощью функции `strcmp`.

```c
int strcmp(const char *s1, const char *s2);
```

Функция возвращает значение 0, если две строки равны, какое-то положительное значение,
если строка `s1` лексикографически больше строки `s2` и какое-то отрицательное значение,
если строка `s1` лексикографически меньше строки `s2`. Лексикографическое сравнение
двух байтов выполняется как если бы тип `char` был беззнаковым. То есть знаковость
типа `char` никак не влияет на работу этой функции, сравнение строк всегда
будет правильным.

Функция `strcasecmp` аналогична функции `strcmp`, но выполняет сравнение без учета
регистра букв. По умолчанию она работает только для заглавных и строчных
латинских букв по кодировке ASCII,
для заглавных и строчных букв других языков сравнение будет побайтовое, с учётом регистра.

В указанный дескриптор потока вывода строку можно вывести либо с помощью функции `fputs`,
либо с помощью функций `fprintf` или `printf`.

```c
const char *s = "Hello";
fputs(s, stdout);           // выводим строку на стандартный поток вывода, без перехода на новую строку
printf("%s", s);            // или так
fprintf(stdout, "%s\n", s); // выводим строку на стандартный поток вывода с переходом на новую строку
printf("%s\n", s);          // или так
```

Современные компиляторы умеют оптимизировать вызовы `printf` и преобразовывать их в более эффективные вызовы.

Функция `sscanf` позволяет выполнять форматное преобразование из строки, а не из файла.
Например,

```c
    char buf[64] = "  15    1.5";
    int val1;
    double val2;
    int r = sscanf(buf, "%d%lf", &val1, &val2);
    // получим r == 2, val1 == 15, val2 == 1.5
```

Некоторые функции стандартной библиотеки, например, `strcpy`, `strcat`, `sprintf` принимают
указатель на массив `char`, в который нужно записать результат, но не принимают размер массива. При этом если места в памяти для размещения считываемых данных не хватит,
произойдет переполнение буфера. Такие функции можно использовать только после того, как выполнены
проверки, что в массиве, в который будет записан результат, достаточно места.

Для преобразования числа в строку можно использовать `sprintf`. К сожалению, в стандартной библиотеке
языка C других способов преобразования числа в строку нет.

```c
int val = 42;
char buf[64];   // верим, что строковое представление 32-битного знакового целого числа уместится в 63 байта
sprintf(buf, "%d", val); 
```

В принципе, современные компиляторы умеют анализировать форматную строку и параметры функций семейства
`printf`. Они выдадут предупреждение, если переполнение буфера будет потенциально возможным.

«Правильные» функции стандартной библиотеки C, которые формируют строку в результате работы,
принимают два параметра для указания места, в которую нужно записать результат: указатель на массив
для хранения строки и длину массива.

Например, для форматного преобразования в строку полезна функция `snprintf`.

```c
int snprintf(char *buf, size_t size, const char *format, ...);
```

Форматное преобразование выполняется в массив `buf` размера `size`, причём максимально в него может
быть записано `size-1` значащих байтов формируемой строки. В конце сформированной строки
будет записан нулевой байт. Функция возвращает длину строки, которая бы получилась,
если массив `buf` был бы очень большого размера. Возвращаемое значение удобно использовать
для проверки того, что выходная строка не поместилась в буфер целиком.

```c
void work(int x, const char *s) // s может быть произвольной длины
{
    char buf[64];
    if (snprintf(buf, sizeof(buf), "x: %d, s: %s", x, s) >= (int) sizeof(buf)) {
        snprintf(buf, sizeof(buf), "OUTPUT TOO LONG"); // здесь можно и strcpy
    }
    send_to_client(buf);
}
```

Функция `snprintf` полезна при работе с путями файловой системы, поскольку в
POSIX-совместимых системах
определена константа `PATH_MAX`, ограничивающая максимальную длину строки пути, который
возможно обработать в системных вызовах.

Для чтения строки текста из входного потока используется функция `fgets`.

```c
char *fgets(char *buf, size_t size, FILE *f);
```

Эта функция считывает байты из входного потока `f` до байта перехода на новую строку `'\n'`
включительно,
либо пока не будет считано `size-1` байтов. Если байт перехода на новую строку считан,
он будет помещен в массив `buf`. После считанных байтов всегда будет добавлен нулевой байт,
формируя таким образом строку по правилам C. Но нулевой байт может быть считан из файла
и окажется в середине считанной строки. Тогда хвост строки, который находится после нулевого байта,
хотя и будет считан из файла, окажется недоступным для обработки стандартными функциями, так как
нулевой байт, считанный из файла, неотличим от нулевого байта, добавленного функцией `fgets`.

В случае успешного чтения функция возвращает значение, переданное в `buf`. В случае ошибки,
в частности в случае конца файла возвращается `NULL`. Типичное использование функции `fgets`
для чтения файла показано ниже.

```c
    char buf[1024]; // ожидаем, что во входном потоке не будут встречаться строки длиннее 1023 байтов с учётом \n

    while (fgets(buf, sizeof(buf), stdin)) { // читаем из stdin до признака конца файла (или ошибки)
        size_t len = strlen(buf);
        // ... обрабатываем строку buf
    }
```

Проблема с этим кодом в том, что если строка во входном файле окажется длиннее 1023, она будет разорвана
на части несколькими вызовами `fgets`. Более удобна для чтения функция `getline`, о которой поговорим далее.

У функций семейства `scanf` есть форматное преобразование `%s` для чтения в строку. Но, к сожалению,
длина массива не передаётся в качестве параметра в функцию `scanf`, поэтому приходится использовать
специальный формат.

```c
    char buf[64];
    int r = scanf("%63s", buf);
```

В этом случае на стандартном потоке ввода сначала пропускаются все пробельные байты,
затем в массив `buf` будет считано не более чем 63 непробельных байта до первого пробельного байта
или конца файла. Форматное преобразование `%63s` указывает, что максимально в строку можно считать 63 байта.
Такое использование тоже не очень удобно: во-первых, из-за необходимости задавать ограничение на длину
считываемой строки в текстовом виде в строке формата; во-вторых, из-за того, что,
если длина строки во входном файле больше 63 байта, остаток не будет считан.
**Использование простого спецификатора формата `%s` возможно только в исключительных случаях!**

Напоминаем, что пробельными байтами называются те байты, для которых
функция `isspace` возвращает `true`. Это пробел ` `, табуляция `\t`,
вертикальная табуляция `\v` и переходы на новую строку `\r` и `\n`.

### Контролируемое преобразование из строки в число

Часто требуется преобразовать строку в число целого или вещественного типа,
при этом проверить корректность записи числа. Требуется, чтобы
при чтении числа не возникало переполнение, в хвосте числа не находится «мусор».
Следущие записи считаются недопустимыми: `""` (пустая строка),
`"   "` (только пробельные байты в строке),
`"1231a"` (мусор в конце строки), `"1 "` (пробел в конце строки),
`"11111111111111111111111111111111111111111111"` (число не представимо значением
целого типа). Следущие записи допустимы: `"12"`, `"   -12"` (пробелы перед числом допускаются).

Для такого рода преобразований используются функции `strtol` (преобразование в long), `strtoll` (преобразование в long long),
`strtoul` (преобразование в unsigned long), `strtoull` (преобразование в unsigned long long), `strtod` (преобразование в double).
Они определены в заголовочном файле `<stdlib.h>`.

Рассмотрим использование `strtol`.
```
    long strtol(const char *str, char **eptr, int radix);
```

Функция возвращает преобразованное значение. Если значение числа непредставимо в типе `long`, в переменную `errno`
записывается код ошибки `ERANGE`.

В переменную, адрес которой передан вторым параметром, записывается указатель на первый байт, который не является
частю считанного числа, то есть либо адрес нулевого байта-терминатора, либо адрес начала «мусора» после числа.
Если в строке вообще нет цифр, во второй параметр сохраняется `str`.

Параметр `radix` задает систему счисления для перевода. Он может принимать значения от 2 до 36.
Если `radix` равен 0, функция пытается определить систему счисления по правилам записи целых чисел языка C по префиксу числа: `0x` &mdash; шестнадцатеричное, `0` &mdash; восьмеричное, иначе десятичное.

Поэтому проверка корректности чтения с помощью `strtol` заключается в следующем:
* проверить, что строка не пуста;
* проверить, что переменная `errno` не установлена;
* проверить, что `eptr` указывает на нулевой байт.

Кроме того, если мы хотим преобразовать из строки в число значение типа `int`, у нас нет
выбора, кроме как конвертировать в `long`, а затем проверить, что значение является предствимым в типе `int`.
Это можно сделать следующим образом:

```c
#include <stdlib.h>
#include <errno.h>

int mustatoi(const char *str)
{
    char *eptr;
    errno = 0; // очищаем errno
    long value = strtol(str, &eptr, 10); // один из немногих случаев, где нужен тип long
    if (eptr == str || *eptr || errno || (int) value == value) {
        // ошибка преобразования из строки в число
        fprintf(stderr, "failed to convert '%s' to int\n", str);
        abort();
    }
    return (int) value;
}
```

Выражение `(int) value == value` проверяет, что цепочка преобразований `long -> int -> long`
не меняет значение числа, то есть число, находящееся в переменной типа `long`,
может быть помещено в переменную типа `int` без потери значащих бит.

## Работа с динамической памятью

Язык C относится к языкам с явным управлением динамической памятью. У него нет
сборщика мусора, хотя он возможен, и неперемещающие сборщики мусора для C существуют
(boehm garbage collector). У него нет автоматического освобождения выделенной
памяти с помощью подсчёта ссылок. Работа с динамической памятью ведётся
с помощью явных вызовов функций выделения и освобождения памяти.

Выделение памяти выполняется с помощью функции `malloc`.

```c
void *malloc(size_t size);
```

Функция возвращает `NULL`, если память выделить невозможно из-за её исчерпания.
В случае успеха возвращается указатель на начало выделенного массива байт размера `size`.
Гарантируется, что указатель выровнен правильно для размещения любого встроенного
типа данных. Выделенная память не инициализирована и содержит непредсказуемые
значения. Функция `malloc` вполне пригодна
для выделения памяти, чтобы скопировать существующий массив или строку,
но в остальных случаях предпочтительнее использовать функцию `calloc`.

```c
void *calloc(size_t nelem, size_t size);
```

Функция выделяет память под массив из `nelem` элементов, размер каждого элемента `size`.
Функция возвращает `NULL`, если память выделить невозможно из-за её исчерпания.
В случае успеха возвращается указатель на начало выделенного массива байт.
Гарантируется, что указатель выровнен правильно для размещения любого встроенного
типа данных. У функции `calloc` два преимущества перед `malloc`:
* проверяется, что результат умножения `nelem*size` не переполняет тип `size_t`;
* выделенная память инициализируется нулями.
Поэтому практически всегда использование `calloc` предпочтительнее использования `malloc`.

Функция `free` освобождает память, выделенную с помощью функций выделения динамической
памяти стандартной библиотеки C (это `malloc`, `calloc`, `realloc`, `strdup` и некоторые другие).

```c
void free(void *ptr);
```

Функция не делает ничего, если `ptr == NULL`. Обратите внимание, что функции не нужно передавать
размер, запрошенный при выделении. Размер блока хранится в служебных структурах,
с помощью которых стандартная библиотека управляет динамической памятью.

Функция `realloc` позволяет изменить размер уже выделенного блока. Функция старается
оставить блок на месте, но, если это невозможно, перенесёт его на новое место,
и новый указатель на начало может быть не равен старому.

```c
void *realloc(void *oldptr, size_t newsize);
```

Если изменить размер невозможно, то функция возвращает NULL, но старое выделение,
на которое указывает `oldptr`, сохраняется. В случае успеха возвращается
указатель на начало блока размера `newsize`. Он может быть равен `oldptr`,
а может не быть равен. Если размер блока был увеличен, то дополнительно
выделенная память неинициализирована. Если `oldptr == NULL`, то функция
работает как `malloc` Если `newsize == 0`, то поведение функции
зависит от реализации: работает либо как `free`, либо как `malloc(0)`.

Нестандартная функция `reallocarray`:

```c
void *reallocarray(void *oldptr, size_t nelem, size_t size);
```

отличается от обычной `realloc` только тем, что проверяется переполнение при
умножении `nelem*size`.

### Обработка ошибок выделения памяти

Функции выделения динамической памяти возвращают NULL, если память выделить
не удалось. Использовать динамическое выделение так, как на примере, неправильно.

```c
    int *p = malloc(sizeof(*p));
    *p = 100;
```

В случае, если выделение памяти завершилось неуспешно, переменная `p` получит значение `NULL`,
и её разыменование приведёт к неопределённому поведению. На практике программа завершится
аварийно с диагностикой `Segmentation fault`, но, как сказано выше, нет никаких гарантий,
что такое поведение сохранится на других компиляторах, других операционных системах или
на других версиях того же самого компилятора. Поэтому указатель, полученный от функций
выделения памяти, обязательно должен проверяться.

Однако ответить на вопрос «*Как нужно обрабатывать ошибки выделения памяти?*» сложнее.
Самый простой вариант &mdash; вернуть наверх в вызывающую функцию какое-то значение,
сигнализирующее об ошибке, например, тот же `NULL`, переложив ответственность
на обработку ошибки выделения памяти на вызывающую функцию.
С другой стороны, очень часто не видно какой-либо разумной стратегии обработки
ошибки нехватки памяти. Тогда проще всего в случае нехватки памяти
вывести сообщение об ошибке нехватки памяти и
завершить программу аварийно с помощью `abort()`, предоставив разработчикам выяснять
причину падения программы и причину нехватки памяти.

Например, предположим, что мы реализуем вектор (расширяемый массив)
для элементов типа `int`. Структура для хранения информации о векторе
будет примерно такая:

```c
struct VectorInt
{
    int    *data;  // сами данный
    size_t  alloc; // под сколько элементов выделена память
    size_t  use;   // сколько элементов используется
};
```

Мы хотим написать функцию добавления элемента в конец вектора.
Наивная реализация будет такой:

```c
void VectorInt_push_back(struct VectorInt *p, int v)
{
    if (p->use == p->alloc) { // требуется расширение
        if (!(p->alloc *= 2)) p->alloc = 4; // начальный размер
        p->data = realloc(p->data, p->alloc*sizeof(p->data[0]));
    }
    p->data[p->use++] = v;
}
```

Этот код работает корректно в случае, если при выполнении не возникает ошибок.
Поскольку никаких ошибок в нём не проверяется, если что-то пойдёт не так,
мы попадем в неопределённое поведение.

Допустим, мы хотим возвращать булевское значение для того, чтобы вызывающая
функция могла получить флаг ошибки и предпринять какие-то действия.

Напишем новый вариант.
```c
[[nodiscard]] _Bool VectorInt_push_back(struct VectorInt *p, int v)
{
    if (p->use == p->alloc) { // требуется расширение
        if (!p->alloc) {
            p->alloc = 4; // начальный размер
        } else {
            if ((ssize_t) p->alloc < 0) {
                // не можем умножить на 2, так как переполнимся
                return 0;
            }
            p->alloc *= 2;
        }
        int *p = reallocarray(p->data, p->alloc, sizeof(p->data[0]));
        if (!p) {
            // перевыделение памяти было неуспешно
            return 0;
        }
        p->data = p;
    }
    p->data[p->use++] = v;
    return 1;
}
```

С помощью `[[nodiscard]]` мы даём указание компилятору убедиться,
что возвращаемое значение функции не игнорируется.

Вариант функции, который использует `realloc` вместо `reallocarray` и
завершается аварийно по `abort()` вместо возврата 0, оставлен читателю в качестве упражнения.

## Санитайзеры

При работе с динамической памятью могут быть допущены различные ошибки, некоторые из которых перечислены ниже:

* неосвобождение блока динамической памяти (утечка памяти &mdash; memory leak);
* повторное освобождение блока динамической память (double free);
* выход за пределы выделенного блока динамической памяти (out of bounds);
* обращение по нулевому указателю (null pointer access).

Ошибки повторного освобождения выделенной памяти или выхода за пределы блока особенно коварны тем,
что их эффект обычно проявляется сильно позже того, когда были допущены в программе. То есть после ошибочного
вызова или обращения к памяти программа ещё какое-то время работает и обрабатывает данные,
прежде чем аварийно завершиться, иногда по совершенно не связанной с данной ошибкой причине.

Для выявления таких ошибок очень полезны санитайзеры, которые являются частью компиляторов
gcc и clang. Санитайзер &mdash; это сочетание специального режима компиляции программы,
когда потенциально опасные операции окружаются дополнительными проверками, причём 
это делается на уровне генерации машинного кода, и поддержки во время выполнения программы, которая
помогает отслеживать ошибочные обращения и сообщать о них пользователю.

Чтобы скомпилировать программу с включёнными санитайзерами добавьте в опции компилятора
два флага: `-fsanitize=undefined,address -fno-sanitize-recover`.
Первая опция включает два санитайзера: на неопределённое поведение при выполнении
арифметических и некоторых других операций, на некорректную работу с памятью (выход
за пределы массива, двойное освобождение) и на утечки памяти. Вторая опция приведёт к
тому, что программа немедленно завершится, если ошибка будет обнаружена.

Программа, скомпилированная с включёнными санитайзерами, работает заметно медленнее, и, если нет
диагностированных ошибок, её поведение ничем не отличается от программы без санитайзеров.
Но если при выполнении была диагностирована ошибка, то на стандартный поток
ошибок будет выведено подробное сообщение об ошибке по-возможности с указанием
позиции в исходном коде, в которой произошла ошибка.

## Работа со строками с использованием динамической памяти

Рассмотрим несколько стандартных и расширенных функций, присутствующих
в библиотеке языка C на Linux, которые работают со строками, размещая их в динамической
памяти. Они свободны от некоторых недостатков, упомянутых при описании функций
работы со строками, работающих с массивами фиксированного размера.

Функция `strdup` выделяет блок динамической памяти для размещения строки
и копирует туда строку. Если память выделить не удалось, функция возвращает NULL.
Если функции передаётся нулевой указатель, её поведение не определено.
Выделенная память должна быть освобождена с помощью `free`.

```c
char *strdup(const char *s);
```

Функция `getline` считывает строку текста из входного потока.
Строка текста завершается либо байтом перехода на новую строку `'\n'`,
либо признаком конца файла. В конце считанной строки добавляется нулевой байт.

```c
ssize_t getline(char **p_line, size_t *p_size, FILE *f);
```

В параметрах `p_line` и `p_size` передаются адреса двух переменных, в которых
функция хранит указатель на начало выделенного буфера под строку и
размер выделенного буфера. Функция возвращает `-1` при достижении конца файла или ошибке,
либо количество считанных из входного потока байт при успешном выполнении.
Типичное использование функции для чтения входного потока примерно такое:

```c
    // в начале буфер пуст
    char *buf = NULL;
    size_t size = 0;
    ssize_t rlen;

    while ((rlen = getline(&buf, &size, stdin)) >= 0) {
        // очередная строка успешно считана, ее длина находится в rlen
        // обрабатываем строку в buf
    }
    free(buf); // не забываем освободить
```

Форматное преобразование `%ms` можно использовать вместо форматного преобразования `%s`
для чтения строки с помощью `scanf`. В этом случае считанная строка будет размещена
в динамической памяти.

```c
    char *buf = NULL;
    int r = scanf("%ms", &buf);
    // обрабатываем buf
    free(buf); // не забываем освободить
```

Функцию `asprintf` можно использовать вместо `snprintf`. Она выделяет память для
выходной строки в динамической памяти. Например,

```c
    char *res = NULL;
    asprintf(&res, "value: %d, name: %s", value, name);
    // результат форматного преобразования находится в строке res
    free(res); // не забываем освободить
```

Для формирования выходного потока в памяти можно использовать функцию `open_memstream`.

```c
    char *text = NULL;
    size_t size = 0;
    FILE *f = open_memstream(&text, &size);
    fprintf(f, "Hello:");
    fprintf(f, "value: %d, name: %s");
    fclose(f);
    // теперь в переменной text находится строка, сформированная выводом в f
    free(text); // не забываем освободить
```

Эта функция может быть особенно удобна, когда строка формируется по частям
несколькими операциями или даже в цикле.

## Работа со стековой памятью

Локальные переменные и параметры вызываемых функций находятся на стеке
исполняющейся программы. Подробнее об устройстве стеков мы поговорим
в соответствующем разделе. При входе в функцию на стеке выделяется
память для локальных переменных, а при выходе из функции все
локальные переменные и другие выделения на стеке у текущей
функции освобождаются. Аллокация и деаллокация памяти на стеке выполняется
намного быстрее, чем в области динамической памяти. Выделение
памяти на стеке &mdash; это, как правило, одна инструкция процессора,
а выделение памяти в области динамической памяти производится
по достаточно сложной логике с блокировкой от параллельного исполнения
несколькими нитями и ещё с возможным обращением к ядру операционной
системы для запроса памяти у ядра.

На стеке можно выделять память не фиксированного заранее размера
либо с помощью массива переменного размера (VLA), который
был кратко упомянут выше, либо с помощью функции `alloca`.

Может показаться, что всегда предпочтительнее выделять память на стеке.
Это так, но выделение памяти на стеке связано с несколькими
ограничениями.

Во-первых, дисциплина освобождения памяти на стеке, когда при завершении
функции освобождается всё, что было выделено функцией на стеке,
не позволяет хранить там объекты, которые должны остаться в памяти
после завершения функции.

Во-вторых, максимальный размер стека у работающей программы ограничен
и обычно намного меньше, чем максимальный размер доступной программе
динамической памяти. Например, на Linux по умолчанию для работающей
программы доступно всего 8MiB стека. Если стек переполнится,
программа аварийно завершится.

Это значит, что выделять на стеке область размером в 1MiB и больше
уже очень опасно, можно легко переполнить стек. Более того, даже
локальные переменные размером в десятки килобайт могут переполнить
стек при рекурсии средней глубины. Рекурсивные функции нельзя использовать там,
где в процессе обработки рекурсия может быть очень глубокой,
например при обработке несбалансированных деревьев или при поиске в глубину
в графе. В этих случаях нужно либо использовать нерекурсивные варианты
соответствующих алгоритмов, либо моделировать рекурсию вручную,
моделируя стек в области динамической памяти.
